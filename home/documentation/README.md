# Monolix configuration guide

Monolix is a single-host NixOS and Home Manager flake for an HP Victus
15-fb2117ax. It builds one flake output, `athena`, from `hosts/athena` for the
`atharva` user. The flake, repository and Git remote are all named `monolix`.

The desktop is **Hyprland** with the **Kuro** QuickShell shell. Kuro is also the
source of truth for colors, fonts, wallpaper and visual settings: it renders
the files consumed by Quickshell, Zsh, Flea, Hyprland and kitty. Nix installs
the tooling and seeds the Kuro configuration, but it does not own the generated
theme outputs.

## Overview

- **Flake** — `flake.nix` defines `nixosConfigurations.athena`, wiring in
  Home Manager, Lanzaboote, the system modules, core Home Manager modules and
  the Hyprland profile.
- **User** — `atharva`; Home Manager state version `26.05`, with a
  `backupFileExtension` so existing user files are preserved when Home Manager
  first takes ownership.
- **Host** — `hosts/athena/athena.nix` plus a generated
  `hardware-configuration.nix`; locale `en_IN`, timezone `Asia/Kolkata`,
  systemd-boot or Lanzaboote, and a `lts` specialisation on the stable kernel.
- **Desktop** — SDDM starts Hyprland with autologin; the Kuro shell runs under
  Quickshell from Hyprland autostart.
- **Hardware** — Ryzen 7 8845HS, Radeon 780M and RTX 4050. PRIME offload is
  configured; run a program on the NVIDIA GPU with `nvidia-offload <app>`.

There is a single desktop profile: `athena`. `KURO_FLAKE` is set to
`~/.config/nixconfig` in the session, so `kuro` works from any directory.
Override it, or pass `--flake PATH`, to use a different flake. `KURO_PROFILE`
(default `athena`) and `KURO_USER` (default `atharva`) provide the other
defaults.

## The `kuro` command

`kuro` is the Rust CLI shipped by Home Manager for the build, activation and
maintenance workflow. It wraps `nixos-rebuild`, `nix build`, `nix-env` and
friends, and prints the underlying commands with `--verbose` or `--dry-run`.

```sh
kuro help                      # full command list
kuro sync                      # rebuild system + activate live
kuro boot                      # rebuild system + stage for next boot
kuro home                      # activate Home Manager only
kuro build                     # build without activating
kuro test                      # activate temporarily until reboot
kuro --profile athena test     # explicitly select the only profile
kuro --dry-run sync            # print commands without running them
kuro --verbose home            # echo commands as they run
kuro --flake "$KURO_FLAKE" sync

kuro status                    # current system and Home Manager generations
kuro generations home          # list available generations
kuro check                     # evaluate the flake without building
kuro info                      # flake, profile and tool versions
kuro path                      # detected flake directory
kuro doctor                    # check the local setup
kuro-theme-check               # validate every shipped Kuro palette
kuro clean --keep 5            # keep five Home Manager generations
kuro system clean --keep 5     # same for system generations
kuro gc                        # collect unreachable store paths
kuro jump                      # return to the previous Home Manager generation
kuro jump --pick               # choose a generation with fzf
kuro update                    # update flake inputs and write flake.lock
kuro edit [FILE]               # open the flake or a file in it with $EDITOR

kuro search fastfetch          # search Nixpkgs
kuro run hello --greeting hi   # run a package once
kuro try ripgrep fd            # temporary shell with extra packages
kuro fhs ./some-linux-installer  # run a downloaded binary in an FHS shell
kuro menu                      # pick a command with fzf
```

The installed `kuro` can rebuild itself through the bootstrap entry point when
it is stale or cannot locate the flake; it builds the current Home Manager
activation package from an explicit `path:` flake reference.

## Kuro theme workflow

Kuro owns appearance end to end:

- **Theme definitions (managed by Nix):** one TOML per scheme in
  `home/home-manager/theme/colors/`, installed read-only to
  `~/.config/kuro/themes/`. Each file implements the full Kuro color contract;
  run `python3 home/home-manager/theme/colors/check_palettes.py` (or
  `kuro-theme-check` after activation) before adding or changing a scheme.
- **Active setting (managed by kurogen):** `~/.config/kuro/kuro.toml` holds
  the selected scheme, Hyprland look, fonts, terminal settings and app
  defaults. `kurogen` seeds the base file on first run, so a fresh account can
  edit it immediately.
- **Switch or tweak:**
  ```sh
  kurogen themes                    # list available schemes
  kurogen scheme tokyo-night        # switch scheme
  kurogen set theme.gaps_in 0       # change one value in kuro.toml
  kurogen                           # regenerate everything
  kurogen path                      # print the config path
  ```
  The shell also watches `kuro.toml` and can apply changes from its Appearance
  page, including regenerating configs and reloading Hyprland and kitty.
- **Generated, do not edit by hand:** `~/.cache/kuro/theme.json`,
  `~/.cache/kuro/zsh-colors.zsh`, `~/.config/hypr/kuro.lua` and
  `~/.config/kitty/kuro.conf`. These are rendered by `kurogen` from `kuro.toml`
  and the selected theme file. Nix does not manage or rewrite these generated
  theme outputs; `kurogen` does.

The base `kuro.toml` seed lives in `home/home-manager/config/desktop/kuro`;
edit it only when changing the defaults shipped by the flake. The shell's own
source is in `home/home-manager/config/desktop/quickshell/kuro`.

## Hyprland session

`modules/desktop/hyprland.nix` enables Hyprland with XWayland and configures
SDDM to automatically log into the `hyprland` session as `atharva`. The compositor
config lives under `home/home-manager/config/desktop/hyprland`:

- `hyprland.lua` sets the keyboard layout and input options; XKB swaps Alt and
  Super, so the `MOD` used in the keybind file is the physical Alt key.
- `conf.d/keybinds.lua` binds the shell actions, for example `MOD+A` or
  `MOD+Space` for the launcher, `MOD+V` for clipboard history, `MOD+TAB` for
  overview, `MOD+N` for notifications, `MOD+B` for the sidebar, `MOD+F` for the
  Flea file manager, `MOD+L` to lock, `MOD+Shift+B` for the next bar layout and
  `Print` for the capture overlay. Workspaces `1`–`0` are bound to `MOD+<key>`.
- `conf.d/autostart.lua` starts `awww-daemon`, launches the shell with
  `quickshell -p ~/.config/quickshell/shell`, starts `hypridle`, and watches
  text and image selections into `cliphist`.
- `conf.d/animations.lua`, `media.lua`, `monitor.lua`, `rules.lua` and
  `environment.lua` hold the remaining compositor settings; `hypridle.conf`
  handles idle locking and screen blanking.

The QuickShell Kuro shell is installed at `~/.config/quickshell/shell` and is
also controllable over IPC (`qs -c shell ipc call ...`). It provides the bar,
launcher, overview, notifications, lock screen, capture overlay, sidebar and
Control Center pages, and reads its palette from `~/.cache/kuro/theme.json`.
See the [shell reference](../home-manager/config/desktop/quickshell/kuro/README.md)
for page and bar-layout details.

Wayland portals prefer the Hyprland portal with GTK as a fallback; the host
also enables the GNOME portal for shared xdg-desktop-portal consumers.

## Power management

`modules/power/laptop.nix` sets `amd_pstate=active` so the Ryzen 7 8845HS
driver balances boost clocks against thermals. Policy is handled by
`services.tuned` with `ppdSupport = true`: its tuned-ppd compatibility service
speaks the standard power-profiles D-Bus API, so the shell's power page and
`powerprofilesctl` continue to work without a separate daemon. The default is
`balanced`, with profile recommendations for desktop and virtual guests.

`services.upower.enable = true` supplies battery information, and the lid-close
module handles suspend/lock behavior.

## Secure Boot (Lanzaboote)

Secure Boot is controlled by `athena.secureboot.enable` in
`hosts/athena/athena.nix` (currently enabled). `modules/boot/secureboot.nix`
always installs `sbctl`; when the option is on, Lanzaboote replaces
systemd-boot with signed unified kernel images and reads its keys from
`/var/lib/sbctl`.

To set it up on a fresh machine:

```sh
sudo sbctl create-keys                    # creates keys in /var/lib/sbctl
# set athena.secureboot.enable = true in hosts/athena/athena.nix
kuro sync                                 # signs and installs the boot entries
sudo sbctl verify                         # confirm the entries are signed
```

Reboot into firmware setup, enter Secure Boot Setup Mode, boot back into
NixOS, then enroll the keys (keeping the Microsoft certificates for option
ROMs) and verify enforcement:

```sh
sudo sbctl enroll-keys --microsoft
sudo reboot
bootctl status                            # Secure Boot: enabled (user)
```

Do not enable enforcement in firmware until `sbctl verify` reports the boot
entries as signed. Back up `/var/lib/sbctl` securely: its private keys are
required to sign future boot entries.

## Updates and maintenance

There is no checked-in `flake.lock`; the first build generates one. Update
inputs with `kuro update` (or `kuro update <input>` for one input), then apply
with `kuro sync`. Use `kuro home` for user-only changes. `kuro test` activates
a generation temporarily until reboot, and `kuro --dry-run sync` previews the
commands.

Inspect generations with `kuro status` and `kuro generations`, roll back with
`kuro jump`, prune with `kuro clean --keep 5` or `kuro system clean --keep 5`,
and collect store garbage with `kuro gc`. Run `kuro doctor` to check local
tools and `kuro check` to evaluate the flake without building.

System packages are intentionally minimal; most tools are installed per user
through Home Manager. Disks come from `hosts/athena/hardware-configuration.nix`;
regenerate it with `nixos-generate-config` when moving to different hardware.

## Remote copy

`origin` points at `https://github.com/athxrvx/monolix.git`. From a clone,

```sh
git push -u origin HEAD
```

pushes the current branch. If a downloaded archive has no `.git` directory,
